# Policy CMS intake and controlled newsletter QA

This release addresses the gap between policy documents in Git and actual CMS page records. It does not itself publish a policy or assert legal approval.

The existing authenticated editorial REST credential can be used with a separately enabled `POLICY_DRAFT_INTEGRATION_ENABLED` flag. `/api/policies/v1/pages` lists only privacy-policy, terms-of-use and cookies-and-analytics. POST `/api/policies/v1/pages/{slug}/draft` requires an explicit expected_revision_id (null for a new record), then delegates to the same SitePageController save path as the staff CMS. Existing published pointers are preserved. Reads and previews require authentication, return no-store/noindex, and cannot access unrelated page slugs. There is no publication endpoint and no change to OAuth editorial MCP scopes.

The separate `NEWSLETTER_OPERATOR_TEST_ENABLED` flag permits one controlled test per UTC day to `johnkiunga01+ar-newsletter-qa-YYYYMMDD@gmail.com`, an owner-controlled Gmail alias. No supplied recipient can override this target. POST `/api/launch-tests/v1/newsletter` requires confirm_test=1 and uses the existing NewsletterController and configured mail transport. Public signup is enabled only within that single private request, then immediately restored in a finally block. It is never activated globally by this test. The authenticated response can contain the one-use confirmation URL captured from the actual accepted mail message; retain it only in private client storage, never logs, screenshots, Git or chat.

SMTP acceptance is not proof of inbox delivery. Obtain owner receipt confirmation separately. GET `/api/launch-tests/v1/newsletter/{id}` reports only eligible owner test aliases and provides a signed unsubscribe URL for end-to-end verification. It cannot read or produce opt-out links for real subscribers. Existing live confirmation and unsubscribe pages require explicit POST and their normal CSRF/signature checks. Nginx omits confirmation and unsubscribe capability URLs from access logs. No campaign sender is introduced or invoked.

Disable both operator flags when the run finishes. The normal staff CMS remains the place for owner/legal approval and page publication. Do not enable GA4_ENABLED, GA4_PRIVACY_NOTICE_APPROVED or NEWSLETTER_SIGNUP_ENABLED until the owner's specified launch gates have passed. Administrator MFA, unrelated credentials and editorial article revisions stay outside this release.
